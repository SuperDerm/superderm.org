Data and Privacy

SuperDerm handles clinical photographs of skin disease. This page explains how photographs are stored, prepared, reviewed, shown and logged.

Storage#

  • Uploads go to private staging storage. Storage keys are random IDs. Original file names, which may contain names, stay in restricted records.
  • Original files never leave storage. Everyone, data stewards included, works with derived copies.
  • Contact details, case histories, diagnoses and evidence references are kept in restricted records on the server.

Derived Images#

After a photo is imported, a background worker:

  1. checks the real file format, accepting JPEG and PNG, and refuses multi-frame files and files over 80 million pixels;
  2. applies the EXIF orientation, so the photo is upright;
  3. converts it to sRGB and removes all embedded metadata, including EXIF and GPS location;
  4. saves a JPEG display copy and a small thumbnail;
  5. computes a perceptual hash and flags possible duplicates for human review. Duplicates are never merged automatically.

Privacy Review#

Each derived image waits as "awaiting privacy review" until a data steward clears or rejects it. The steward clears an image only if it shows no faces, tattoos, legible text or other identifying details, or if the source's permissions cover them. Until then, the photo can be used for nothing but a catalog entry.

Cropping or masking an image is Planned. Until it is available, the steward rejects an image that needs it and asks the source for a corrected file.

Privacy Reports#

Anyone working on a photo can select Report Privacy Concern. The photo is paused at once for every use, its tasks stop being claimable, and the project's data stewards are notified. It stays paused until a steward clears or rejects it. See Report an issue.

The Media Gateway#

Controlled photos are never served by ID or from a fixed public address.

  1. When a page needs a photo, the server checks your account, your role or assignment, and the photo's permitted uses.
  2. It issues a ticket: a signed link bound to you, the purpose (annotation, review or privacy review), the exact image revision, and an expiry 5 minutes later.
  3. The gateway under /superderm/media/ checks the ticket, that you are the signed-in user it names, and your current authorization, on every request.

If any check fails, the gateway answers "not found" and reveals nothing else. Withdrawal, suspension or the end of your access takes effect on the next request. The workspace fetches fresh tickets automatically when one expires.

Gateway responses are marked Cache-Control: private, no-store, carry the generic file name photo.jpg, and may only be loaded by SuperDerm pages. API responses are marked no-store. Annotation drafts are never stored in your browser.

Practice photos and teaching cases are separate public files that have been approved for display. They do not pass through the gateway.

What Is Logged#

The audit log records who did what to which object and when, with the stated reason and small details such as counts or versions. Examples: claims, submissions, review decisions, role grants and revocations, privacy decisions, imports and releases. Server logs record object IDs and error codes.

Never logged: photographs, case histories or other clinical text, diagnostic evidence, private links, access tickets and request bodies.

Emails contain only a sign-in link, never case details.

No Third-Party Analytics#

The platform loads no third-party analytics or tracking scripts, and none run on case, annotation, review or download screens. Fonts are served by the site itself. Other sites cannot embed SuperDerm pages, and pages may not use your camera, microphone or location.

Development Mailbox#

In development and preview environments without an outgoing mail server, messages the platform would send, such as sign-in links, are kept in a development mailbox at /dev/mailbox instead of being sent. The server log records only the recipient and subject.

Anyone who can open a preview environment can read its mailbox, including sign-in links. Use preview environments only with test accounts. In production the mailbox does not exist, and email must go through the configured mail server.

Releases#

Release packages contain only independently reviewed annotations on photographs cleared for redistribution, with their derived images. Source identifiers, original file names, case histories, diagnoses, contact details, annotators' notes, "Term not listed" descriptions and reviewers' internal notes are left out. See Release package format.

Intended Use#

SuperDerm is a research platform. It is not intended for clinical, diagnostic or therapeutic purposes.
