Data Access and Withdrawal

Every photograph carries a record of what it may be used for. The platform applies the same record in the interface and on the server, on every request.

Use Categories#

Use Permits Where the current build enforces it
catalog A catalog entry or external link only; no image is sent Recorded. The only use allowed before privacy review
view Viewing on the platform by authorized contributors Recorded. A separate view-only mode is Planned
annotate Community annotation on the platform Queue counts, claims, the media gateway for annotators and reviewers, and submission
display Public display as a teaching case Recorded. Teaching cases are a separately approved list
redistribute Inclusion in downloadable releases Release freeze and package build
train Training research models Recorded. Training manifests are Planned
evaluate Blinded evaluation in challenges Recorded. Challenge evaluation is Planned

Each use is decided separately. Permission to annotate says nothing about redistribution or training.

Closed by Default#

A use is allowed only when all of these hold:

  1. The source, the case and the photo are active: not paused, suspended or withdrawn.
  2. For every use except catalog, the photo's derived image has passed privacy review.
  3. The source explicitly allows the use, and that decision has not expired or been revoked.
  4. The photo's rights statement (the rights_ref in a manifest) allows the use, and has not expired.
  5. No narrower decision on the case or the photo blocks it.

An unknown or missing decision keeps the use closed.

Narrowing Only#

A case or a single photo can carry its own decision for a use. It can only narrow what the source and rights statement allow.

Decision on a case or photo Effect
None, or inherit Follows the source and rights statement
deny or unknown Blocks the use
Expired or revoked Blocks the use
allow Cannot loosen a restriction above it

Annotation queues also skip photos reserved for development, test, blind-test or teaching sets, whatever their permissions.

Getting Access#

  • Public releases. Anyone can download a published public release package.
  • Annotation. Sign in, accept the rules, join the project, pass the practice task and claim a task. You can see a photo only through an assignment that includes it. See Getting started.
  • Review. Hold the clinical reviewer role for the project. You see only photos of tasks you did not work on, from cases you did not contribute.
  • Controlled access. Requests for controlled material, naming the use, version, purpose and period, are Planned.

When a reviewer or staff role is revoked or expires, the photos you could see through it stop loading. See Roles and permissions.

Withdrawal#

Effects#

When a source, case or photo is marked withdrawn:

  • the media gateway stops serving its photos on the next request, and any ticket already issued expires within 5 minutes;
  • its tasks stop being claimable, open tasks that include it cannot be submitted, and the workspace shows that the photo is no longer available;
  • public counts drop it at once, because they are computed from current records;
  • it is excluded from any release frozen afterwards. If a photo loses redistribution permission between the freeze and the build, the build fails and the release manager starts a new draft.

Published packages are immutable and are not edited. Withdrawing a published release, with a notice and a replacement manifest, is Planned. The download link already handles it: a withdrawn release returns its withdrawal notice instead of the file.

Asking for Withdrawal#

A withdrawal or narrowing request from the item's record, returning a ticket ID, is Planned. Until it is available:

  • to stop a photo being shown at once, report it with the privacy category; it is paused immediately;
  • for anything else, send the request through Report an issue, with the ID of the item.

What Cannot Be Recalled#

Copies already downloaded outside the platform cannot be recalled. This is why withdrawal notices will state their scope. The planned workflow keeps a minimal audit record of each withdrawal, while patient details and authorization documents stay private.

Intended Use#

Releases and access are for research only. SuperDerm is not intended for clinical, diagnostic or therapeutic purposes.
