Report an Issue

Report privacy problems, licensing questions, label errors, technical faults and scoring disputes here. You must be signed in. Never put patient-identifiable information in a report.

Categories#

Category Value Use it for
Privacy privacy A face, tattoo, name, legible text or other detail that could identify a person
Licensing licensing Missing or wrong permissions, licences or attribution
Label error label_error A wrong diagnosis, term or region in a resource or release
Technical technical Something on the site does not work
Scoring dispute scoring_dispute A vocabulary mapping or score you believe is wrong
Other other Anything else, including requests that have no form yet

Privacy Concerns About a Photo#

A privacy report about a photo pauses it immediately:

  • the photo stops being shown anywhere, for any use;
  • its tasks stop being claimable;
  • the project's data stewards are notified. The photo stays paused until a steward clears or rejects it in privacy review.

From the annotation workspace:

  1. Select Report Privacy Concern in the panel footer.
  2. Describe what may identify a person, for example a face, tattoo, name or legible text. Describe the kind of detail, not the detail itself.
  3. Select Pause Photo and Report.

You see "Thank you. The photo is paused while a data steward reviews your report." You cannot submit the task while the photo is paused. If the steward does not clear it, skip the task.

Only a privacy report about a photo pauses distribution automatically. A privacy report about a case, resource or page is recorded like any other issue.

Other Issues#

A form for issues other than photo privacy is Planned. Until it is available, signed-in users can file any report through the API: POST /api/v1/issues, served at /superderm/api/v1/issues.

Field Required Value
object_type Yes photo, case, resource, release, challenge or page
object_id Yes The ID or slug, for example superderm-taxonomy, up to 80 characters
object_version No The version you used, for example a release or vocabulary version
category Yes One of the values above
description Yes 5 to 2,000 characters

The API accepts changes only from SuperDerm's own pages, with your session. The simplest way is your browser's developer console, opened on any SuperDerm page while you are signed in:

await fetch("/superderm/api/v1/issues", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    object_type: "resource",
    object_id: "superderm-taxonomy",
    object_version: "1.0.0",
    category: "label_error",
    description: "What is wrong, and where you saw it."
  })
}).then((r) => r.json());

The response contains an issue_id, beginning is_, and the status open. A privacy report about a photo returns the status suspended instead. Keep the ID. See API overview for error responses.

What to Include#

  • The object and its version: a release version, vocabulary version, photo or case ID, or the page address.
  • What is wrong, and where you saw it.
  • For a label error, the value you believe is correct and why.
  • No names, record numbers or other identifiers, ever.

What Happens Next#

Staff see every report on the Issues page with its category, object, description and status. Each report starts as open. Assigning reports, recording the decision and its reason, and replying to the reporter are Planned.

A correction to released data appears in a new release version. Published versions are never edited. See Release package format.

A monitored contact address for the project has not been confirmed yet. Until it is, this page is the way to reach the project team.
