1f:T1602,<h1>Report an Issue</h1>
<p>Report privacy problems, licensing questions, label errors, technical faults and scoring disputes here. You must be signed in. Never put patient-identifiable information in a report.</p>
<h2 id="categories">Categories<a class="heading-anchor" href="#categories" aria-label="Link to this section">#</a></h2>

<h2 id="privacy-concerns-about-a-photo">Privacy Concerns About a Photo<a class="heading-anchor" href="#privacy-concerns-about-a-photo" aria-label="Link to this section">#</a></h2>
<p>A privacy report about a photo pauses it immediately:</p>
<ul>
<li>the photo stops being shown anywhere, for any use;</li>
<li>its tasks stop being claimable;</li>
<li>the project&#39;s data stewards are notified. The photo stays paused until a steward clears or rejects it in privacy review.</li>
</ul>
<p><strong>From the annotation workspace:</strong></p>
<ol>
<li>Select <strong>Report Privacy Concern</strong> in the panel footer.</li>
<li>Describe what may identify a person, for example a face, tattoo, name or legible text. Describe the kind of detail, not the detail itself.</li>
<li>Select <strong>Pause Photo and Report</strong>.</li>
</ol>
<p>You see &quot;Thank you. The photo is paused while a data steward reviews your report.&quot; You cannot submit the task while the photo is paused. If the steward does not clear it, skip the task.</p>
<p>Only a privacy report about a photo pauses distribution automatically. A privacy report about a case, resource or page is recorded like any other issue.</p>
<h2 id="other-issues">Other Issues<a class="heading-anchor" href="#other-issues" aria-label="Link to this section">#</a></h2>
<p>A form for issues other than photo privacy is Planned. Until it is available, signed-in users can file any report through the API: <code>POST /api/v1/issues</code>, served at <code>/superderm/api/v1/issues</code>.</p>
<table>
<thead>
<tr>
<th>Field</th>
<th>Required</th>
<th>Value</th>
</tr>
</thead>
<tbody><tr>
<td><code>object_type</code></td>
<td>Yes</td>
<td><code>photo</code>, <code>case</code>, <code>resource</code>, <code>release</code>, <code>challenge</code> or <code>page</code></td>
</tr>
<tr>
<td><code>object_id</code></td>
<td>Yes</td>
<td>The ID or slug, for example <code>superderm-taxonomy</code>, up to 80 characters</td>
</tr>
<tr>
<td><code>object_version</code></td>
<td>No</td>
<td>The version you used, for example a release or vocabulary version</td>
</tr>
<tr>
<td><code>category</code></td>
<td>Yes</td>
<td>One of the values above</td>
</tr>
<tr>
<td><code>description</code></td>
<td>Yes</td>
<td>5 to 2,000 characters</td>
</tr>
</tbody></table>
<p>The API accepts changes only from SuperDerm&#39;s own pages, with your session. The simplest way is your browser&#39;s developer console, opened on any SuperDerm page while you are signed in:</p>
<pre><code class="language-js">await fetch(&quot;/superderm/api/v1/issues&quot;, {
  method: &quot;POST&quot;,
  headers: { &quot;Content-Type&quot;: &quot;application/json&quot; },
  body: JSON.stringify({
    object_type: &quot;resource&quot;,
    object_id: &quot;superderm-taxonomy&quot;,
    object_version: &quot;1.0.0&quot;,
    category: &quot;label_error&quot;,
    description: &quot;What is wrong, and where you saw it.&quot;
  })
}).then((r) =&gt; r.json());
</code></pre>
<p>The response contains an <code>issue_id</code>, beginning <code>is_</code>, and the status <code>open</code>. A privacy report about a photo returns the status <code>suspended</code> instead. Keep the ID. See <a href="/docs/reference/api">API overview</a> for error responses.</p>
<h2 id="what-to-include">What to Include<a class="heading-anchor" href="#what-to-include" aria-label="Link to this section">#</a></h2>
<ul>
<li>The object and its version: a release version, vocabulary version, photo or case ID, or the page address.</li>
<li>What is wrong, and where you saw it.</li>
<li>For a label error, the value you believe is correct and why.</li>
<li>No names, record numbers or other identifiers, ever.</li>
</ul>
<h2 id="what-happens-next">What Happens Next<a class="heading-anchor" href="#what-happens-next" aria-label="Link to this section">#</a></h2>
<p>Staff see every report on the <strong>Issues</strong> page with its category, object, description and status. Each report starts as open. Assigning reports, recording the decision and its reason, and replying to the reporter are Planned.</p>
<p>A correction to released data appears in a new release version. Published versions are never edited. See <a href="/docs/reference/release-format">Release package format</a>.</p>
<p>A monitored contact address for the project has not been confirmed yet. Until it is, this page is the way to reach the project team.</p>
