Train and Evaluate a Model

This page takes you from data to a scored model in five steps. Training happens on your own machine or cloud account; SuperDerm provides data, the vocabulary, the prediction format and the scorer.

For research discussion only. Everything on SuperDerm, including model outputs and scores, is not medical advice and does not constitute a medical diagnosis.

1. Get the Data#

Source What it gives you Terms
Public datasets Public clinical-photograph datasets used in the SuperDerm research Each provider's own licence; some are non-commercial only
SuperDerm Community Annotations Reviewed regions, morphology terms and image-quality labels, released by version with checksums The licence shown on each release
SuperDerm Diagnostic Taxonomy 214 diagnoses with synonyms, used by the scorer to match names See the dataset page
SuperDerm-424K v0.1 Labels, splits and quality tiers for 350,565 photographs from five public datasets; images come from each provider, and the included match_images.py links them Each source's own licence; three are non-commercial

Read the release package format before you parse a release. Coordinates are fractions of the upright photo, from the top-left corner.

2. Train#

Use any framework. Two rules keep evaluations fair:

  • Never train on a challenge's test cases or on anything derived from them.
  • Record which data and versions you used. The model card asks for them, and every published score names them.

3. Write Predictions#

Write one JSON object per line, in UTF-8. Each row has exactly case_id and predictions: up to three free-text diagnoses, most likely first. An empty list is an explicit abstention.

{"case_id":"s_demo_001","predictions":["Mpox","Varicella","Herpes Zoster"]}
{"case_id":"s_demo_005","predictions":[]}

The scorer maps names to the taxonomy, including listed synonyms. Names it cannot map score zero. See the community scoring protocol.

4. Score#

The scorer is in the evaluator/ folder of the SuperDerm-Release repository. It needs Python 3.10 or newer and no other packages. Run it on the development fixtures first to check your pipeline:

cd evaluator
python3 -m superderm_eval validate --predictions fixtures/dev/predictions.jsonl --cases fixtures/dev/cases.txt
python3 -m superderm_eval score --predictions fixtures/dev/predictions.jsonl \
    --reference fixtures/dev/reference.csv --config fixtures/dev/config.json

Challenge reference answers stay hidden. When a challenge opens for evaluation, you upload predictions on its page and the same scorer runs on the server. Until then, prediction upload is Planned.

5. Share Your Model#

List your model with Share a Model or Tool. Your code and weights stay in your own repository; you give a pinned revision, licences, a reproducible command and known limitations. A maintainer checks the instructions, and results are labelled reproduced only after a rerun. See Share a model or tool.
