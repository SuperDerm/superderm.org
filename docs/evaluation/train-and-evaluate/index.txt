1f:T1173,<h1>Train and Evaluate a Model</h1>
<p>This page takes you from data to a scored model in five steps. Training happens on your own machine or cloud account; SuperDerm provides data, the vocabulary, the prediction format and the scorer.</p>
<p><strong>For research discussion only.</strong> Everything on SuperDerm, including model outputs and scores, is not medical advice and does not constitute a medical diagnosis.</p>

<h2 id="2-train">2. Train<a class="heading-anchor" href="#2-train" aria-label="Link to this section">#</a></h2>
<p>Use any framework. Two rules keep evaluations fair:</p>
<ul>
<li>Never train on a challenge&#39;s test cases or on anything derived from them.</li>
<li>Record which data and versions you used. The model card asks for them, and every published score names them.</li>
</ul>
<h2 id="3-write-predictions">3. Write Predictions<a class="heading-anchor" href="#3-write-predictions" aria-label="Link to this section">#</a></h2>
<p>Write one JSON object per line, in UTF-8. Each row has exactly <code>case_id</code> and <code>predictions</code>: up to three free-text diagnoses, most likely first. An empty list is an explicit abstention.</p>
<pre><code class="language-json">{&quot;case_id&quot;:&quot;s_demo_001&quot;,&quot;predictions&quot;:[&quot;Mpox&quot;,&quot;Varicella&quot;,&quot;Herpes Zoster&quot;]}
{&quot;case_id&quot;:&quot;s_demo_005&quot;,&quot;predictions&quot;:[]}
</code></pre>
<p>The scorer maps names to the taxonomy, including listed synonyms. Names it cannot map score zero. See the <a href="/docs/evaluation/scoring">community scoring protocol</a>.</p>
<h2 id="4-score">4. Score<a class="heading-anchor" href="#4-score" aria-label="Link to this section">#</a></h2>
<p>The scorer is in the <code>evaluator/</code> folder of the <a href="https://github.com/SuperDerm/SuperDerm-Release">SuperDerm-Release repository</a>. It needs Python 3.10 or newer and no other packages. Run it on the development fixtures first to check your pipeline:</p>
<pre><code class="language-bash">cd evaluator
python3 -m superderm_eval validate --predictions fixtures/dev/predictions.jsonl --cases fixtures/dev/cases.txt
python3 -m superderm_eval score --predictions fixtures/dev/predictions.jsonl \
    --reference fixtures/dev/reference.csv --config fixtures/dev/config.json
</code></pre>
<p>Challenge reference answers stay hidden. When a challenge opens for evaluation, you upload predictions on its page and the same scorer runs on the server. Until then, prediction upload is Planned.</p>
<h2 id="5-share-your-model">5. Share Your Model<a class="heading-anchor" href="#5-share-your-model" aria-label="Link to this section">#</a></h2>
<p>List your model with <a href="/contribute">Share a Model or Tool</a>. Your code and weights stay in your own repository; you give a pinned revision, licences, a reproducible command and known limitations. A maintainer checks the instructions, and results are labelled reproduced only after a rerun. See <a href="/docs/contributing/models">Share a model or tool</a>.</p>
