Community Scoring Protocol

Challenges score open-ended diagnosis. For each case, a model returns up to three free-text diagnoses, most likely first. The community scorer, superderm-eval version 1.0.0, validates the predictions file and scores it against a hidden reference. Its code is published, so anyone with the same inputs can reproduce a score byte for byte.

Online prediction submission is Planned. Today you can run the scorer locally.

Prediction Format#

UTF-8 JSON Lines, one object per case:

{"case_id":"s_demo_001","predictions":["Mpox","Varicella","Herpes Zoster"]}
{"case_id":"s_demo_005","predictions":[]}
  • Each row has exactly two keys, case_id and predictions.
  • predictions holds 0 to 3 strings, most likely first.
  • An empty list is an explicit abstention. It scores zero and stays in every denominator.
  • Every expected case has exactly one row, in any order. case_id is compared exactly.
  • A leading byte-order mark is removed, blank lines are ignored, and \r\n line endings work.

Participants check a file against a case list: plain UTF-8 text, one case_id per line.

Validation#

A file is either valid or rejected. A rejected file is never scored, and every problem is reported with its line number.

Code Meaning
invalid_utf8, invalid_json A line is not valid UTF-8 or JSON
duplicate_key, row_not_object, invalid_keys A row is not an object with exactly case_id and predictions
case_id_not_string case_id is not a string
unknown_case_id The case is not in the expected list
duplicate_case_id The case already appeared
missing_case_ids Expected cases have no row
predictions_not_array predictions is not a list
too_many_predictions More than three entries
prediction_not_string An entry is not a string
blank_prediction An entry is empty after normalization
duplicate_prediction Two entries are the same text, or map to the same diagnosis, such as "Smallpox" and "Variola"

Normalization and Matching#

Answers and vocabulary names are normalized the same way: Unicode NFKC, case folding, leading and trailing whitespace removed, and each internal run of whitespace replaced by one space. Nothing else changes. There is no spelling correction or fuzzy matching: " MPOX " and "monkeypox" match Mpox (DX-070), but "M-pox" does not.

An answer matches when it equals the canonical name or a synonym of exactly one diagnosis in vocabulary superderm-diagnoses 1.0.0, which has 214 diagnoses and 63 synonyms. The synonyms are a draft until clinically approved, and every result reports synonyms_status. Unknown answers, and ambiguous names shared by two diagnoses, score zero; they are not validation errors.

Metrics#

For k = 1, 2 or 3:

  • hit@k is 1 if any of the case's first k answers matches its reference diagnosis, otherwise 0. A case scores at most one hit at each k.
  • acc@k, top-k accuracy, is the sum of hit@k divided by the fixed number of reference cases. Abstentions stay in the denominator.
  • macro_recall@k takes acc@k over the cases of each diagnosis in a chosen set that has at least one reference case, then averages over those diagnoses. Results report n_cases, n_diagnoses and n_diagnoses_in_set.

Example: three mpox cases all found and one smallpox case missed give a macro recall of (1 + 0) / 2 = 0.5, and an accuracy of 3/4 = 0.75.

A metric can be limited to a cohort label or to a set of diagnoses. If no case remains, the value is null, with a reason. Arithmetic is exact, and each value is rounded once, to 6 decimals.

The first challenge's primary metric is macro recall@3 over the prespecified rare, high-consequence diagnoses. Its secondary metrics are top-1 and top-3 accuracy over all cases and over common mimics.

Ties and Versions#

  • Rankings use the published 6-decimal values. Equal values share a rank and the next rank is skipped: 1, 1, 3.
  • Every result records scorer_version, challenge_id, challenge_version, the vocabulary id, version and content_sha256, and predictions_sha256. The same inputs always give byte-identical output.
  • A config whose scorer or vocabulary version differs from the files in use is an error, not a warning.
  • When evaluation opens, each team may make two valid submissions per UTC calendar day.

Run the Scorer Locally#

You need Python 3.10 or newer. The scorer uses the standard library only. From the repository root:

cd evaluator
python3 -m superderm_eval validate --predictions fixtures/dev/predictions.jsonl --cases fixtures/dev/cases.txt
python3 -m superderm_eval score --predictions fixtures/dev/predictions.jsonl \
    --reference fixtures/dev/reference.csv --config fixtures/dev/config.json
python3 -m superderm_eval vocab-check
python3 -m unittest discover -s tests -v

The general forms are:

python3 -m superderm_eval validate --predictions P (--cases LIST | --reference REF) [--vocab V]
python3 -m superderm_eval score    --predictions P --reference REF --config C [--vocab V] [--per-case]
python3 -m superderm_eval vocab-check [--vocab V]
  • --vocab defaults to ../content/vocab/diagnoses.v1.json, relative to evaluator/. Pass it when you run from elsewhere.
  • --per-case reveals the reference diagnoses, so it is for maintainers only.
  • Every command prints one JSON document. Exit code 0 means valid or scored; 1 means the predictions file is invalid; 2 means any other problem, such as a bad argument or a version mismatch.

On the synthetic development fixture, score reports acc@1 = 0.4, acc@3 = 0.6 and a primary macro_recall@3 of 1.0.

Before comparing a challenge score with a published number, read How the preprint's evaluation differs.
