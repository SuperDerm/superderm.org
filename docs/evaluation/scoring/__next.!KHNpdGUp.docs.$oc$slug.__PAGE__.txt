22:T1eda,<h1>Community Scoring Protocol</h1>
<p>Challenges score open-ended diagnosis. For each case, a model returns up to three free-text diagnoses, most likely first. The community scorer, <code>superderm-eval</code> version 1.0.0, validates the predictions file and scores it against a hidden reference. Its code is published, so anyone with the same inputs can reproduce a score byte for byte.</p>
<p>Online prediction submission is Planned. Today you can run the scorer locally.</p>
<h2 id="prediction-format">Prediction Format<a class="heading-anchor" href="#prediction-format" aria-label="Link to this section">#</a></h2>
<p>UTF-8 JSON Lines, one object per case:</p>
<pre><code class="language-json">{&quot;case_id&quot;:&quot;s_demo_001&quot;,&quot;predictions&quot;:[&quot;Mpox&quot;,&quot;Varicella&quot;,&quot;Herpes Zoster&quot;]}
{&quot;case_id&quot;:&quot;s_demo_005&quot;,&quot;predictions&quot;:[]}
</code></pre>
<ul>
<li>Each row has exactly two keys, <code>case_id</code> and <code>predictions</code>.</li>
<li><code>predictions</code> holds 0 to 3 strings, most likely first.</li>
<li>An empty list is an explicit abstention. It scores zero and stays in every denominator.</li>
<li>Every expected case has exactly one row, in any order. <code>case_id</code> is compared exactly.</li>
<li>A leading byte-order mark is removed, blank lines are ignored, and <code>\r\n</code> line endings work.</li>
</ul>
<p>Participants check a file against a case list: plain UTF-8 text, one <code>case_id</code> per line.</p>
<h2 id="validation">Validation<a class="heading-anchor" href="#validation" aria-label="Link to this section">#</a></h2>
<p>A file is either valid or rejected. A rejected file is never scored, and every problem is reported with its line number.</p>

<h2 id="normalization-and-matching">Normalization and Matching<a class="heading-anchor" href="#normalization-and-matching" aria-label="Link to this section">#</a></h2>
<p>Answers and vocabulary names are normalized the same way: Unicode NFKC, case folding, leading and trailing whitespace removed, and each internal run of whitespace replaced by one space. Nothing else changes. There is no spelling correction or fuzzy matching: <code>&quot;  MPOX &quot;</code> and <code>&quot;monkeypox&quot;</code> match Mpox (DX-070), but <code>&quot;M-pox&quot;</code> does not.</p>
<p>An answer matches when it equals the canonical name or a synonym of exactly one diagnosis in vocabulary <code>superderm-diagnoses</code> 1.0.0, which has 214 diagnoses and 63 synonyms. The synonyms are a draft until clinically approved, and every result reports <code>synonyms_status</code>. Unknown answers, and ambiguous names shared by two diagnoses, score zero; they are not validation errors.</p>
<h2 id="metrics">Metrics<a class="heading-anchor" href="#metrics" aria-label="Link to this section">#</a></h2>
<p>For k = 1, 2 or 3:</p>
<ul>
<li><strong>hit@k</strong> is 1 if any of the case&#39;s first k answers matches its reference diagnosis, otherwise 0. A case scores at most one hit at each k.</li>
<li><strong>acc@k</strong>, top-k accuracy, is the sum of hit@k divided by the fixed number of reference cases. Abstentions stay in the denominator.</li>
<li><strong>macro_recall@k</strong> takes acc@k over the cases of each diagnosis in a chosen set that has at least one reference case, then averages over those diagnoses. Results report <code>n_cases</code>, <code>n_diagnoses</code> and <code>n_diagnoses_in_set</code>.</li>
</ul>
<p>Example: three mpox cases all found and one smallpox case missed give a macro recall of (1 + 0) / 2 = 0.5, and an accuracy of 3/4 = 0.75.</p>
<p>A metric can be limited to a <code>cohort</code> label or to a set of diagnoses. If no case remains, the value is <code>null</code>, with a reason. Arithmetic is exact, and each value is rounded once, to 6 decimals.</p>
<p>The first challenge&#39;s primary metric is macro recall@3 over the prespecified rare, high-consequence diagnoses. Its secondary metrics are top-1 and top-3 accuracy over all cases and over common mimics.</p>
<h2 id="ties-and-versions">Ties and Versions<a class="heading-anchor" href="#ties-and-versions" aria-label="Link to this section">#</a></h2>
<ul>
<li>Rankings use the published 6-decimal values. Equal values share a rank and the next rank is skipped: 1, 1, 3.</li>
<li>Every result records <code>scorer_version</code>, <code>challenge_id</code>, <code>challenge_version</code>, the vocabulary <code>id</code>, <code>version</code> and <code>content_sha256</code>, and <code>predictions_sha256</code>. The same inputs always give byte-identical output.</li>
<li>A config whose scorer or vocabulary version differs from the files in use is an error, not a warning.</li>
<li>When evaluation opens, each team may make two valid submissions per UTC calendar day.</li>
</ul>
<h2 id="run-the-scorer-locally">Run the Scorer Locally<a class="heading-anchor" href="#run-the-scorer-locally" aria-label="Link to this section">#</a></h2>
<p>You need Python 3.10 or newer. The scorer uses the standard library only. From the repository root:</p>
<pre><code class="language-sh">cd evaluator
python3 -m superderm_eval validate --predictions fixtures/dev/predictions.jsonl --cases fixtures/dev/cases.txt
python3 -m superderm_eval score --predictions fixtures/dev/predictions.jsonl \
    --reference fixtures/dev/reference.csv --config fixtures/dev/config.json
python3 -m superderm_eval vocab-check
python3 -m unittest discover -s tests -v
</code></pre>
<p>The general forms are:</p>
<pre><code>python3 -m superderm_eval validate --predictions P (--cases LIST | --reference REF) [--vocab V]
python3 -m superderm_eval score    --predictions P --reference REF --config C [--vocab V] [--per-case]
python3 -m superderm_eval vocab-check [--vocab V]
</code></pre>
<ul>
<li><code>--vocab</code> defaults to <code>../content/vocab/diagnoses.v1.json</code>, relative to <code>evaluator/</code>. Pass it when you run from elsewhere.</li>
<li><code>--per-case</code> reveals the reference diagnoses, so it is for maintainers only.</li>
<li>Every command prints one JSON document. Exit code 0 means valid or scored; 1 means the predictions file is invalid; 2 means any other problem, such as a bad argument or a version mismatch.</li>
</ul>
<p>On the synthetic development fixture, <code>score</code> reports acc@1 = 0.4, acc@3 = 0.6 and a primary macro_recall@3 of 1.0.</p>
<p>Before comparing a challenge score with a published number, read <a href="/docs/evaluation/paper-protocol">How the preprint&#39;s evaluation differs</a>.</p>
