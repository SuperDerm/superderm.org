1f:T24a8,<h1>Release Package Format</h1>
<p>SuperDerm community annotations are published as versioned, immutable packages. A package contains only annotations approved by an independent clinical reviewer, on photographs cleared for redistribution. The schema version is <code>superderm-release-1</code>.</p>
<h2 id="download">Download<a class="heading-anchor" href="#download" aria-label="Link to this section">#</a></h2>
<ol>
<li>Open <a href="/datasets/superderm-community-annotations">SuperDerm community annotations</a> and find the version under <strong>Versions</strong>.</li>
<li>Note its SHA-256, then select <strong>Download</strong> for that version.</li>
</ol>
<p>The file is named <code>superderm-community-annotations-&lt;version&gt;.zip</code>. Anyone can download a published public version, without an account. Superseded versions stay downloadable so that results can be reproduced. Versions use semantic numbers such as <code>0.1.0</code>, and a number is never reused.</p>
<p>From the API, <code>GET /api/v1/releases</code> lists published versions with their release ID, SHA-256, size and counts, and <code>GET /api/v1/releases/{release_id}/package</code> returns the zip with an <code>X-Content-SHA256</code> header.</p>
<h2 id="verify">Verify<a class="heading-anchor" href="#verify" aria-label="Link to this section">#</a></h2>
<p>Check the zip against the SHA-256 shown on the dataset page:</p>
<pre><code class="language-sh">shasum -a 256 superderm-community-annotations-0.1.0.zip
</code></pre>
<p>Then unzip it and check every file from inside its folder:</p>
<pre><code class="language-sh">cd superderm-community-annotations-0.1.0
shasum -a 256 -c SHA256SUMS
</code></pre>
<p>Every line should end in <code>OK</code>. On Linux, <code>sha256sum -c SHA256SUMS</code> does the same.</p>
<h2 id="files">Files<a class="heading-anchor" href="#files" aria-label="Link to this section">#</a></h2>
<p>The zip holds one folder, <code>superderm-community-annotations-&lt;version&gt;/</code>:</p>
<table>
<thead>
<tr>
<th>File</th>
<th>Contents</th>
</tr>
</thead>
<tbody><tr>
<td><code>README.md</code></td>
<td>Version, counts, verification command, intended use, release notes</td>
</tr>
<tr>
<td><code>DATASET_CARD.md</code></td>
<td>Counts, intended use, inclusion rule, known limitations, sources and licences, contributor credit</td>
</tr>
<tr>
<td><code>CITATION.cff</code></td>
<td>Citation metadata</td>
</tr>
<tr>
<td><code>SCHEMA.md</code></td>
<td>Field definitions and the coordinate convention</td>
</tr>
<tr>
<td><code>cases.jsonl</code></td>
<td>One row per case: <code>case_id</code>, <code>body_site</code>, <code>split</code>, <code>image_ids</code></td>
</tr>
<tr>
<td><code>images.jsonl</code></td>
<td>One row per photograph: <code>image_id</code>, <code>case_id</code>, <code>file</code>, <code>width</code>, <code>height</code>, <code>sha256</code>, <code>source</code>, <code>license</code>, <code>synthetic</code></td>
</tr>
<tr>
<td><code>annotations.jsonl</code></td>
<td>One row per region, image-quality rating or &quot;Unable to assess&quot; result</td>

</tr>
<tr>

<td><code>vocabularies/morphology.json</code>, <code>vocabularies/image-quality.json</code></td>

</tr>
<tr>
<td><code>images/&lt;image_id&gt;.jpg</code></td>
<td>The derived photographs: upright, with metadata removed</td>

<tr>

<td>The SHA-256 of every other file</td>

<p>Images are stored as derived JPEGs, and <code>width</code>, <code>height</code> and <code>sha256</code> describe those files. A package built from synthetic material says so in <code>README.md</code> and <code>DATASET_CARD.md</code>, and marks its images and sources <code>&quot;synthetic&quot;: true</code>.</p>
<h2 id="annotation-rows">Annotation Rows<a class="heading-anchor" href="#annotation-rows" aria-label="Link to this section">#</a></h2>
<p>Every row of <code>annotations.jsonl</code> has:</p>
<table>
<thead>
<tr>
<th>Field</th>
<th>Meaning</th>
</tr>
</thead>
<tbody><tr>
<td><code>annotation_id</code></td>
<td><code>&lt;result_id&gt;-&lt;n&gt;</code></td>
</tr>
<tr>
<td><code>result_id</code></td>
<td>The reviewed result the row belongs to</td>
</tr>
<tr>
<td><code>image_id</code>, <code>case_id</code></td>
<td>The photograph and case. <code>image_id</code> is <code>null</code> on an &quot;Unable to assess&quot; row</td>
</tr>
<tr>
<td><code>task_type</code></td>
<td><code>visible_findings</code> or <code>image_quality</code></td>
</tr>
<tr>
<td><code>guideline_version</code></td>
<td>The annotation guide version</td>
</tr>
<tr>
<td><code>vocabulary</code></td>
<td><code>{&quot;id&quot;, &quot;version&quot;}</code> of the term list, or <code>null</code></td>
</tr>
<tr>
<td><code>evidence_type</code></td>
<td><code>photograph</code></td>
</tr>
<tr>
<td><code>review_status</code></td>
<td><code>approved</code> or <code>approved_with_edits</code></td>
</tr>
<tr>
<td><code>reviewed_at</code></td>
<td>When the result was approved</td>
</tr>
<tr>
<td><code>annotation_revision</code></td>
<td>The submitted revision that was reviewed</td>
</tr>
<tr>
<td><code>credit</code></td>
<td>The annotator&#39;s public credit</td>
</tr>
</tbody></table>
<p>Visible-findings rows add <code>coordinate_space</code> (<code>oriented_normalized</code>), <code>geometry</code>, <code>cannot_localize</code>, <code>term_ids</code> and <code>certainty</code>. Image-quality rows add <code>assessability</code> and <code>flags</code>. An &quot;Unable to assess&quot; result adds <code>unable_to_assess: true</code>. It never means that no lesion is present.</p>
<p>Example row:</p>
<pre><code class="language-json">{&quot;annotation_id&quot;:&quot;res_5wf9zn5rsr-1&quot;,&quot;image_id&quot;:&quot;ph_pt2a9gajbt&quot;,&quot;result_id&quot;:&quot;res_5wf9zn5rsr&quot;,&quot;case_id&quot;:&quot;c_9agz3qebn7&quot;,&quot;task_type&quot;:&quot;visible_findings&quot;,&quot;guideline_version&quot;:&quot;findings-guide-0.1-draft&quot;,&quot;vocabulary&quot;:{&quot;id&quot;:&quot;superderm-morphology&quot;,&quot;version&quot;:&quot;0.1.0-draft&quot;},&quot;evidence_type&quot;:&quot;photograph&quot;,&quot;review_status&quot;:&quot;approved&quot;,&quot;reviewed_at&quot;:&quot;2026-11-21T08:47:54.778Z&quot;,&quot;annotation_revision&quot;:&quot;ar_q3qjvm5fe6&quot;,&quot;credit&quot;:&quot;Anonymous contributor&quot;,&quot;coordinate_space&quot;:&quot;oriented_normalized&quot;,&quot;geometry&quot;:{&quot;type&quot;:&quot;bbox&quot;,&quot;values&quot;:[0.33,0.28,0.65,0.73]},&quot;cannot_localize&quot;:false,&quot;term_ids&quot;:[&quot;MORPH-024&quot;,&quot;MORPH-011&quot;],&quot;certainty&quot;:&quot;certain&quot;}
</code></pre>
<h2 id="coordinates">Coordinates<a class="heading-anchor" href="#coordinates" aria-label="Link to this section">#</a></h2>
<p>Coordinates refer to the upright image, after the EXIF orientation is applied.</p>
<ul>
<li>The origin is the top-left corner; x increases to the right and y downward.</li>
<li>Values are normalized to [0, 1] by the image&#39;s width and height, with 6 decimals.</li>
<li>A box is <code>{&quot;type&quot;: &quot;bbox&quot;, &quot;values&quot;: [x_min, y_min, x_max, y_max]}</code>.</li>
<li>A polygon is <code>{&quot;type&quot;: &quot;polygon&quot;, &quot;values&quot;: [[x, y], ...]}</code>: ordered vertices, implicitly closed.</li>
<li>A finding without location has <code>&quot;geometry&quot;: null</code> and <code>&quot;cannot_localize&quot;: true</code>.</li>
</ul>
<p>To get pixels, multiply x by <code>width</code> and y by <code>height</code> from <code>images.jsonl</code>.</p>
<h2 id="what-is-left-out">What Is Left Out<a class="heading-anchor" href="#what-is-left-out" aria-label="Link to this section">#</a></h2>
<ul>
<li>Photographs without redistribution permission. A result is left out if any of its photos lacks it.</li>
<li>Results that were returned, recorded as insufficient evidence, superseded or withdrawn, and all work from test projects.</li>
<li>Annotators&#39; notes, &quot;Term not listed&quot; descriptions and reviewers&#39; internal notes.</li>
<li>Source case and image identifiers, original file names, patient groupings, histories, diagnoses and contact details.</li>
</ul>
<h2 id="versions-are-immutable">Versions Are Immutable<a class="heading-anchor" href="#versions-are-immutable" aria-label="Link to this section">#</a></h2>
<p>A release is frozen first: the exact reviewed results it contains are recorded, and later work goes into the next draft. A worker then rechecks redistribution permission for every photo and builds the package with its checksums. If a photo lost permission after the freeze, the build fails and a new draft is needed. The download appears only after a successful build is published. Rebuilding the same snapshot gives a byte-identical archive. Corrections appear in a new version, and a published version is never edited.</p>
<p>Cite the exact version you used; see <a href="/docs/reference/citing">How to cite SuperDerm</a>.</p>
