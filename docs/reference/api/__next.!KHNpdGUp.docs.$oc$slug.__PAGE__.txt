22:T2eed,<h1>API Overview</h1>
<p>SuperDerm&#39;s pages use a JSON API, and you can call it too. This page lists every endpoint that exists today.</p>
<h2 id="base-path">Base Path<a class="heading-anchor" href="#base-path" aria-label="Link to this section">#</a></h2>
<p>Pages are served under <code>/superderm</code> and the API under <code>/superderm/api/v1</code>. The paths below start at <code>/api/v1</code>; on the public site, add the <code>/superderm</code> prefix. Request and response bodies are JSON, and responses are marked <code>Cache-Control: no-store</code>.</p>
<h2 id="authentication">Authentication<a class="heading-anchor" href="#authentication" aria-label="Link to this section">#</a></h2>
<ul>
<li>Sign in with an email link: <code>POST /api/v1/auth/signin</code>, then <code>POST /api/v1/auth/verify</code> with the token from the link. This sets the session cookie <code>sd_session</code>.</li>
<li>The cookie is HTTP-only, <code>SameSite=Lax</code>, secure on HTTPS, limited to the base path, and valid for 30 days. There are no API keys.</li>
<li>Public reads need no session. Other endpoints return <code>401</code> without one, and check your role, project and the object&#39;s permitted uses on every request.</li>
</ul>
<h2 id="same-origin-writes">Same-Origin Writes<a class="heading-anchor" href="#same-origin-writes" aria-label="Link to this section">#</a></h2>
<p>Every <code>POST</code>, <code>PUT</code> and <code>PATCH</code> must carry an <code>Origin</code> header matching the site. Requests from other sites, or without the header, get <code>403</code> (&quot;Requests that change data must come from the SuperDerm site.&quot;). In practice, writes come from SuperDerm pages, including the browser console on a SuperDerm page.</p>
<h2 id="idempotency-key">Idempotency-Key<a class="heading-anchor" href="#idempotency-key" aria-label="Link to this section">#</a></h2>
<p>Endpoints marked † accept an <code>Idempotency-Key</code> header of up to 200 characters.</p>
<ul>
<li>The same user, endpoint, key and request body return the original status and response; the work is not repeated.</li>
<li>The same key with a different body returns <code>409 IDEMPOTENCY_KEY_REUSED</code>.</li>
<li>Without the header, the request runs normally.</li>
</ul>
<p>Drafts use version numbers instead: a stale <code>version</code> returns <code>409 DRAFT_VERSION_CONFLICT</code> with the saved copy.</p>
<h2 id="errors">Errors<a class="heading-anchor" href="#errors" aria-label="Link to this section">#</a></h2>
<p>Errors use one envelope:</p>
<pre><code class="language-json">{&quot;error&quot;:{&quot;code&quot;:&quot;INVALID_ANNOTATION&quot;,&quot;message&quot;:&quot;Finding 1: choose at least one term or describe it under “Term not listed”.&quot;,&quot;field&quot;:&quot;regions.0.termIds&quot;,&quot;retryable&quot;:false,&quot;details&quot;:[{&quot;path&quot;:&quot;regions.0.termIds&quot;,&quot;message&quot;:&quot;Finding 1: choose at least one term or describe it under “Term not listed”.&quot;}]}}
</code></pre>
<p><code>code</code> is stable and <code>message</code> is for people. <code>field</code> (the input at fault), <code>row</code> (a manifest row) and <code>details</code> appear only when they apply. <code>retryable</code> says whether the same request may succeed later.</p>
