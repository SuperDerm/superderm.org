1f:Teae,<h1>How to Cite SuperDerm</h1>
<p>When you use SuperDerm in a publication, cite the platform, the exact release versions you used, and the original sources of any data.</p>
<h2 id="the-platform">The Platform<a class="heading-anchor" href="#the-platform" aria-label="Link to this section">#</a></h2>
<p>Until a DOI and repository link are assigned, cite the software as:</p>
<blockquote>
<p>SuperDerm contributors. (2026). SuperDerm [Computer software].</p>
</blockquote>
<p>This is a placeholder. A DOI or repository link will replace it, so check this page again before you publish.</p>
<h2 id="releases">Releases<a class="heading-anchor" href="#releases" aria-label="Link to this section">#</a></h2>
<p>Cite the exact version of every release you used. Versions never change after publication, so the version number identifies the data exactly.</p>
<ol>
<li>Open the dataset page, for example <a href="/datasets/superderm-community-annotations">SuperDerm community annotations</a>, and find your version under <strong>Versions</strong>.</li>
<li>Use the <code>CITATION.cff</code> file inside the package. It gives the title and version, with &quot;SuperDerm contributors&quot; as authors.</li>
<li>Add the package SHA-256 from the dataset page to your data availability statement.</li>
</ol>
<p>For example:</p>
<blockquote>
<p>SuperDerm contributors. (Year). SuperDerm community annotations (Version x.y.z) [Data set].</p>
</blockquote>
<p>Use the year the version was published. If your work depends on the annotation guide or vocabulary, also name the <code>guideline_version</code> and vocabulary version recorded in the rows you used. See <a href="/docs/reference/release-format">Release package format</a>.</p>
<h2 id="vocabularies-and-the-scorer">Vocabularies and the Scorer<a class="heading-anchor" href="#vocabularies-and-the-scorer" aria-label="Link to this section">#</a></h2>
<p>Catalog entries give their own citation lines:</p>
<ul>
<li>SuperDerm diagnostic taxonomy, version 1.0.0.</li>
<li>SuperDerm community scorer, version 1.0.0.</li>
</ul>
<p>For a challenge result, report the scorer version, the challenge version and the vocabulary version with its content hash. All of them appear in the scorer&#39;s output. See <a href="/docs/evaluation/scoring">Community scoring protocol</a>.</p>
<h2 id="source-datasets">Source Datasets<a class="heading-anchor" href="#source-datasets" aria-label="Link to this section">#</a></h2>
<p>A release can include photographs from other sources. <code>sources.json</code> and <code>DATASET_CARD.md</code> in each package list every source with its rights holder, licence and citation. Cite each source you use, and follow its terms.</p>
<p>The <a href="/datasets">Datasets</a> directory also lists external collections with their own citations. SuperDerm links to them for reference and citation only.</p>
<h2 id="the-preprint">The Preprint<a class="heading-anchor" href="#the-preprint" aria-label="Link to this section">#</a></h2>
<blockquote>
<p>Fang C, Cao X, Talio A, Ye W, Porter CW, Rehg JM, Coffee M. SuperDerm: A Benchmark for Open-Ended Diagnosis of Common and Rare Skin Diseases. Preprint, 2026.</p>
</blockquote>
<p>When you quote a result from the preprint, say that it is author-reported and name the model, data split and protocol. See <a href="/docs/evaluation/paper-protocol">How the preprint&#39;s evaluation differs</a>.</p>
<h2 id="credit-to-contributors">Credit to Contributors<a class="heading-anchor" href="#credit-to-contributors" aria-label="Link to this section">#</a></h2>
<p>Release packages list contributor credit in <code>DATASET_CARD.md</code>, following each contributor&#39;s attribution choice. See <a href="/docs/contributing/credit">Contribution and credit</a>.</p>
