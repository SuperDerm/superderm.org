1f:T1614,<h1>Share a Model or Tool</h1>
<p>Use <a href="/contribute">Share a model or tool</a> to submit a model, adapter, tool or reusable script for clinical photographs of skin disease. Keep the work in your own repository and submit a pinned revision. SuperDerm never runs code that participants upload.</p>

<h2 id="preview-and-submit">Preview and Submit<a class="heading-anchor" href="#preview-and-submit" aria-label="Link to this section">#</a></h2>
<ol>
<li>While you fill in the form, the <strong>Preview resource card</strong> beside it shows the title, summary, type and task, with the label &quot;author-reported&quot;.</li>
<li>Select <strong>Preview</strong> to check every field. Missing fields are listed at the top, each linked to its field.</li>
<li>Select <strong>Submit for Review</strong>.</li>
</ol>
<p>Your receipt shows a submission ID that stays the same through revisions, and the submission appears under <strong>Contributions</strong> in <a href="/contribute">My workspace</a>. To continue a saved draft later, select <strong>Resume Draft</strong> there.</p>
<h2 id="author-reported-or-reproduced">Author-Reported or Reproduced<a class="heading-anchor" href="#author-reported-or-reproduced" aria-label="Link to this section">#</a></h2>
<table>
<thead>
<tr>
<th>Label</th>
<th>Meaning</th>
</tr>
</thead>
<tbody><tr>
<td>Author-reported</td>
<td>Review covered the documentation only. The results are the authors&#39; own.</td>
</tr>
<tr>
<td>Reproduced</td>
<td>A maintainer reran your command on an approved example and recorded the output.</td>
</tr>
</tbody></table>
<p>Every new entry starts as author-reported. The results shown on the official SuperDerm model pages come from the preprint, are labelled author-reported, and are not community evaluation runs.</p>
<h2 id="review-and-approval">Review and Approval<a class="heading-anchor" href="#review-and-approval" aria-label="Link to this section">#</a></h2>
<p>Reviewer tools for model submissions are Planned. When review opens, a research maintainer will check the links, dependencies and instructions. Approval creates a separate, citable entry in the <a href="/models">Models</a> directory, with its version and a citation link.</p>
<h2 id="community-adaptations">Community Adaptations<a class="heading-anchor" href="#community-adaptations" aria-label="Link to this section">#</a></h2>
<p>An approved entry that adapts an official resource is listed under <strong>Community Adaptations</strong> on the upstream resource&#39;s page, and the two pages link to each other. Today each official model page shows &quot;No community adaptation has been reviewed yet.&quot;</p>
<p>To publish a new version, submit the new pinned revision from your repository.</p>
<h2 id="comparing-results">Comparing Results<a class="heading-anchor" href="#comparing-results" aria-label="Link to this section">#</a></h2>
<p>To compare models on a challenge, use the <a href="/docs/evaluation/scoring">community scoring protocol</a>, which you can run locally. Name the dataset version, scorer version and protocol behind every number you report. Online prediction submission is Planned. For how manuscript results were scored, see <a href="/docs/evaluation/paper-protocol">How the manuscript&#39;s evaluation differs</a>.</p>
