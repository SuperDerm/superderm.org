22:T2865,<h1>Share a Dataset</h1>
<p>Use <a href="/contribute">Share a dataset</a> to register a published collection, or to deliver an institutional collection privately. Collections with existing annotations are welcome.</p>
<h2 id="two-modes">Two Modes<a class="heading-anchor" href="#two-modes" aria-label="Link to this section">#</a></h2>
<table>
<thead>
<tr>
<th>Mode</th>
<th>What you provide</th>
<th>What the platform does</th>
</tr>
</thead>
<tbody><tr>
<td>Source registration only</td>
<td>A catalogue entry and a link to the published source</td>
<td>Records the entry for review and citation. It never fetches data from the link and never generates images.</td>
</tr>
<tr>
<td>Includes hosted files</td>
<td>Photographs and a manifest, delivered privately through controlled intake</td>
<td>A data steward imports the accepted rows into private staging. Every photo is processed and privacy-reviewed before any use.</td>
</tr>
</tbody></table>
<h2 id="steps">Steps<a class="heading-anchor" href="#steps" aria-label="Link to this section">#</a></h2>
<ol>
<li>On the form page, select <strong>Download Template</strong>. You can read the field definitions before signing in.</li>
<li>Prepare your manifest, then check it with <strong>Validate Your Manifest</strong>. The check runs in your browser and uploads nothing.</li>
<li>Sign in, accept the community rules, and fill in the form. Required: title, description, source institution, contact email, image type, mode, and licence or data-use terms. Optional: citation, existing labels, size, source link, attribution and intended release.</li>
<li>Select <strong>Preview</strong>, then <strong>Submit for Review</strong>. You get a receipt whose ID stays the same through revisions, as for <a href="/docs/contributing/cases#your-receipt">a single case</a>. To finish a saved draft later, select <strong>Resume Draft</strong> under <strong>Contributions</strong> in <a href="/contribute">My workspace</a>.</li>
</ol>
<p>Reviewer tools for dataset submissions are Planned. For hosted files, a data steward arranges the private transfer and runs the import. Uploading a whole collection yourself is Planned.</p>
<p>If the collection includes dermoscopic or histopathology images, choose the mixed image type. Those images go to the data steward and never enter community annotation.</p>
<h2 id="manifest-columns">Manifest Columns<a class="heading-anchor" href="#manifest-columns" aria-label="Link to this section">#</a></h2>
<p>UTF-8 CSV, one row per photograph. Columns are matched by name, so their order does not matter.</p>
<table>
<thead>
<tr>
<th>Column</th>
<th>Required</th>
<th>Meaning</th>
</tr>
</thead>
<tbody><tr>
<td><code>source_case_id</code></td>
<td>Yes</td>
<td>Your case ID within the batch. Rows with the same value form one case.</td>
</tr>
<tr>
<td><code>source_image_id</code></td>
<td>Yes</td>
<td>Your photo ID, unique within the batch.</td>
</tr>
<tr>
<td><code>filename</code></td>
<td>Yes</td>
<td>The uploaded file name, without folders. Never include names or record numbers.</td>
</tr>
<tr>
<td><code>rights_ref</code></td>
<td>Yes</td>
<td>A registered statement of permitted uses, such as <code>R1</code>. Rows may use different statements.</td>
</tr>
<tr>
<td><code>source_patient_group</code></td>
<td>No</td>
<td>Groups photos of the same person within the batch. Leave empty if unknown.</td>
</tr>
<tr>
<td><code>source_diagnosis</code></td>
<td>No</td>
<td>The diagnosis as named by the source.</td>
</tr>
<tr>
<td><code>evidence_ref</code></td>
<td>No</td>
<td>Reference to supporting evidence: pathology, laboratory, genetic, records or publication.</td>
</tr>

<td>No</td>

</tr>

<td>No</td>
<td>For example <code>20-29</code>.</td>
</tr>
</tbody></table>
<p>IDs use letters, digits, dot, dash and underscore, start with a letter or digit, and have at most 64 characters. Values have at most 500 characters. The template shows two photos of one case:</p>
<pre><code class="language-csv">source_case_id,source_image_id,filename,rights_ref,source_patient_group,source_diagnosis,evidence_ref,view_label,body_site,age_band

C001,I002,case1_detail.jpg,R1,G07,,,close-up,forearm,30-39
</code></pre>

<p>The browser check on the form page cannot see registered rights or uploaded files, so <code>UNKNOWN_RIGHTS_REF</code>, <code>MISSING_FILE</code>, <code>DUPLICATE_CONTENT</code> and <code>ALREADY_IMPORTED</code> appear only in the server check. Reports count rows, accepted rows, rows with errors, cases, photos and files separately. <strong>Download Rows with Errors (CSV)</strong> lists each failing row with its number and messages, so you can correct it and validate again.</p>
<h2 id="controlled-intake">Controlled Intake<a class="heading-anchor" href="#controlled-intake" aria-label="Link to this section">#</a></h2>
<p>For hosted files, the data steward uploads the photographs to private staging with SHA-256 checksums, and the server validates the manifest again. Only accepted rows are imported. Rows with errors stay private and editable. Confirming the same rows twice imports them once.</p>
<p>A worker then checks each file, applies its orientation, removes metadata, and flags possible near-duplicates for human review; they are never merged automatically. Files that cannot be decoded, have several frames or exceed the pixel limit are flagged one by one, usually with &quot;export it as JPEG and upload it again&quot;. Each photo then waits for privacy review.</p>
<h2 id="limits">Limits<a class="heading-anchor" href="#limits" aria-label="Link to this section">#</a></h2>
<p>Each photo: JPEG or PNG, up to 25 MiB and 80 million pixels. Each batch: up to 2,000 images and 5 GiB. A manifest: up to 5 MiB.</p>
<h2 id="existing-annotations">Existing Annotations<a class="heading-anchor" href="#existing-annotations" aria-label="Link to this section">#</a></h2>
<p>Describe existing annotations in the form. Importing them from an <code>annotations.jsonl</code> file is Planned. The accepted format is UTF-8, one JSON object per line, each naming a photo in the same batch by <code>source_image_id</code>:</p>
<pre><code class="language-json">{&quot;source_image_id&quot;:&quot;I002&quot;,&quot;source_annotation_id&quot;:&quot;A001&quot;,&quot;coordinate_space&quot;:&quot;oriented_normalized&quot;,&quot;geometry&quot;:{&quot;type&quot;:&quot;bbox&quot;,&quot;values&quot;:[0.2,0.25,0.55,0.7]},&quot;term_ids&quot;:[&quot;MORPH-024&quot;],&quot;taxonomy_version&quot;:&quot;0.1.0-draft&quot;,&quot;review_status&quot;:&quot;source_reported&quot;,&quot;rights_ref&quot;:&quot;R1&quot;}
</code></pre>
<p>Coordinates start at the top left of the upright image, x to the right and y down, normalized to 0–1. A box is <code>[x_min, y_min, x_max, y_max]</code>; a polygon is an ordered list of <code>[x, y]</code> vertices. The manifest also names the source terminology, annotator credit, coordinate reference and licence. The importer will check image references, duplicate annotation keys, coordinates, terms and rights references, and will keep the source&#39;s review status separate from SuperDerm&#39;s own review.</p>
