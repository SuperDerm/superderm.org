Share a Dataset

Use Share a dataset to register a published collection, or to deliver an institutional collection privately. Collections with existing annotations are welcome.

Two Modes#

Mode What you provide What the platform does
Source registration only A catalogue entry and a link to the published source Records the entry for review and citation. It never fetches data from the link and never generates images.
Includes hosted files Photographs and a manifest, delivered privately through controlled intake A data steward imports the accepted rows into private staging. Every photo is processed and privacy-reviewed before any use.

Steps#

  1. On the form page, select Download Template. You can read the field definitions before signing in.
  2. Prepare your manifest, then check it with Validate Your Manifest. The check runs in your browser and uploads nothing.
  3. Sign in, accept the community rules, and fill in the form. Required: title, description, source institution, contact email, image type, mode, and licence or data-use terms. Optional: citation, existing labels, size, source link, attribution and intended release.
  4. Select Preview, then Submit for Review. You get a receipt whose ID stays the same through revisions, as for a single case. To finish a saved draft later, select Resume Draft under Contributions in My workspace.

Reviewer tools for dataset submissions are Planned. For hosted files, a data steward arranges the private transfer and runs the import. Uploading a whole collection yourself is Planned.

If the collection includes dermoscopic or histopathology images, choose the mixed image type. Those images go to the data steward and never enter community annotation.

Manifest Columns#

UTF-8 CSV, one row per photograph. Columns are matched by name, so their order does not matter.

Column Required Meaning
source_case_id Yes Your case ID within the batch. Rows with the same value form one case.
source_image_id Yes Your photo ID, unique within the batch.
filename Yes The uploaded file name, without folders. Never include names or record numbers.
rights_ref Yes A registered statement of permitted uses, such as R1. Rows may use different statements.
source_patient_group No Groups photos of the same person within the batch. Leave empty if unknown.
source_diagnosis No The diagnosis as named by the source.
evidence_ref No Reference to supporting evidence: pathology, laboratory, genetic, records or publication.
view_label No For example overview or close-up.
body_site No Body site.
age_band No For example 20-29.

IDs use letters, digits, dot, dash and underscore, start with a letter or digit, and have at most 64 characters. Values have at most 500 characters. The template shows two photos of one case:

source_case_id,source_image_id,filename,rights_ref,source_patient_group,source_diagnosis,evidence_ref,view_label,body_site,age_band
C001,I001,case1_overview.jpg,R1,G07,,,overview,forearm,30-39
C001,I002,case1_detail.jpg,R1,G07,,,close-up,forearm,30-39

Validation Codes#

Structural errors block the whole file, row errors block the row, and warnings block nothing.

Code Kind Meaning
CSV_SYNTAX Structural A quoted field is never closed.
EMPTY Structural The file is empty.
MISSING_COLUMN Structural A required column is missing.
DUPLICATE_COLUMN Structural A column name repeats.
NO_ROWS Structural A header but no rows.
TOO_MANY_ROWS Structural More than 2,000 photos; split into batches under the same dataset.
COLUMN_COUNT Row The number of values differs from the header.
REQUIRED Row A required value is empty.
INVALID_ID Row An ID has other characters or is too long.
INVALID_FILENAME Row The file name contains a folder or starts with a dot.
UNSUPPORTED_FORMAT Row Not .jpg, .jpeg or .png.
HEIC_NOT_SUPPORTED_YET Row HEIC or HEIF; export the photo as JPEG.
UNKNOWN_RIGHTS_REF Row The rights_ref is not registered for this source.
TOO_LONG Row A value exceeds 500 characters.
MISSING_FILE Row No uploaded file has this name.
DUPLICATE_IMAGE_ID Row A source_image_id appears in several rows.
DUPLICATE_FILENAME Row A file name appears in several rows.
DUPLICATE_CONTENT Row Several rows point to identical file content.
CONFLICTING_CASE_GROUP Row Rows of one case have different source_patient_group values.
UNKNOWN_COLUMNS Warning Unknown columns were ignored.
DIAGNOSIS_PENDING_VERIFICATION Warning A diagnosis without evidence_ref is imported as pending verification.
ALREADY_IMPORTED Warning The photo was already imported from this source and is skipped.

The browser check on the form page cannot see registered rights or uploaded files, so UNKNOWN_RIGHTS_REF, MISSING_FILE, DUPLICATE_CONTENT and ALREADY_IMPORTED appear only in the server check. Reports count rows, accepted rows, rows with errors, cases, photos and files separately. Download Rows with Errors (CSV) lists each failing row with its number and messages, so you can correct it and validate again.

Controlled Intake#

For hosted files, the data steward uploads the photographs to private staging with SHA-256 checksums, and the server validates the manifest again. Only accepted rows are imported. Rows with errors stay private and editable. Confirming the same rows twice imports them once.

A worker then checks each file, applies its orientation, removes metadata, and flags possible near-duplicates for human review; they are never merged automatically. Files that cannot be decoded, have several frames or exceed the pixel limit are flagged one by one, usually with "export it as JPEG and upload it again". Each photo then waits for privacy review.

Limits#

Each photo: JPEG or PNG, up to 25 MiB and 80 million pixels. Each batch: up to 2,000 images and 5 GiB. A manifest: up to 5 MiB.

Existing Annotations#

Describe existing annotations in the form. Importing them from an annotations.jsonl file is Planned. The accepted format is UTF-8, one JSON object per line, each naming a photo in the same batch by source_image_id:

{"source_image_id":"I002","source_annotation_id":"A001","coordinate_space":"oriented_normalized","geometry":{"type":"bbox","values":[0.2,0.25,0.55,0.7]},"term_ids":["MORPH-024"],"taxonomy_version":"0.1.0-draft","review_status":"source_reported","rights_ref":"R1"}

Coordinates start at the top left of the upright image, x to the right and y down, normalized to 0–1. A box is [x_min, y_min, x_max, y_max]; a polygon is an ordered list of [x, y] vertices. The manifest also names the source terminology, annotator credit, coordinate reference and licence. The importer will check image references, duplicate annotation keys, coordinates, terms and rights references, and will keep the source's review status separate from SuperDerm's own review.
